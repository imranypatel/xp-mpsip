# Basic Folder Structure
- Three top level folders represent
	- src - for source code
	- docs - for documentation
	- publish - for release publishing
# PRD driven approach/workflow by concern
- All development on this project is Product Requirement Document (PRD)-driven. Each feature, concern, change, or improvement starts with a PRD file created by the product owner. The agent reads the PRD, resolves ambiguity via Q&A, then plan, get approval of the plan to implements and possible commits
- The Owner creates a PRD document
- PRD docs would be structured as docs/prd/{nn}-{concern}/prd-{nn}-{nn}.md
    - where `{nn}` is a zero-padded sequence and `{concern}` is a short concern label
	- this structuring should enable nesting where the main concern may contain sub-concerns
    - consider each folder under docs/prd as the folder of the main concern
    - A concern may fall into including but not limited to the following domains: Idea, Workflow, Product Management, Application Architecture, Design, Prototype, Modules, Services and Features,Testing, Deployment, DevOps, Reviews, Documentation
    - A concern summary PRD needs to be created to understand the current state of the feature instead of going through all the PRDs related to the concern. This will be helpful for new joiners to understand the feature/concern and also for existing members to get a quick refresher. Summary document name template would be docs/prd/{nn}-{concern}/prd-{nn}-{00}.md where '{00}' is designated for the summary
- The Owner requests agent to plan for the specified PRD
- We may have Q&A where PRD is vague, ambiguous, or incomplete
- You keep initial verbatim of PRD for reference in initial verbatim section as-is i.e. without any additional formatting under the section with the title 'Initial Verbatim'
- You may add revised PRD sections based on our Q&A
- You may add Plan for the PRD in the Plan section of the PRD

# Repository
- Introduce basic versioning system for any revision in any artifact
- Ask whether to keep using the current branch or create a new branch
- Each revision must be triggered based on a PRD
- Do not commit automatically. Ask whether to commit or wait. Commit only when explicitly requested
- Do not push to the origin automatically. Ask whether to push or wait. Push only when explicitly requested
- All commits must be tagged with version number based on the versioning scheme and replicated when pushed to origin.
