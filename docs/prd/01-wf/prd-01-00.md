The **Workflow** concern (`01-wf`) establishes the foundational processes and conventions that govern all development on this project. It defines how work is initiated, planned, implemented, versioned, and published.

## Key Conventions at a Glance

### Folder Structure
```
repo/
├── src/        # Source code
├── docs/       # Documentation (including PRDs)
│   └── prd/
│       └── {nn}-{concern}/
│           ├── prd-{nn}-{00}.md   # Concern summary (this type of file)
│           └── prd-{nn}-{nn}.md   # Individual PRDs
└── publish/    # Release artifacts
```

### PRD-Driven Workflow
1. Owner writes a PRD under `docs/prd/{nn}-{concern}/prd-{nn}-{nn}.md`
2. Agent reads PRD, resolves ambiguity via Q&A
3. Agent adds **Initial Verbatim** section (original PRD content, unformatted) + **Plan** section to the PRD
4. Owner approves plan
5. Agent implements
6. Owner explicitly requests commit and/or push — never automatic

### Versioning
- Scheme: **Semantic versioning** — `v{major}.{minor}.{patch}`
- Every revision is triggered by a PRD
- Commits are tagged with the version; tags are replicated on push

### Branch Policy
- Agent always asks whether to use the current branch or create a new one before making changes
- No auto-commit. No auto-push. Explicit owner request required.
