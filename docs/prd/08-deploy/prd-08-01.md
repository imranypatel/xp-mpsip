# Deployment Runbooks PRD (prd-08-01)

> **Concern**: 08-deploy | **Version**: v0.12.0 | **Phase**: P8

---

## Goal
Document step-by-step runbooks for deploying MPSIP to each environment (DEV, UAT, PROD) on Windows IIS, including prerequisites, environment variable configuration, publish steps, IIS setup, and smoke test checklists.

---

## 1. Prerequisites (All Environments)

| Requirement | Details |
|-------------|---------|
| OS | Windows Server 2019+ or Windows 10/11 (DEV) |
| .NET 10 Runtime | [ASP.NET Core Runtime 10.x](https://dotnet.microsoft.com/download/dotnet/10.0) — install the **Hosting Bundle** |
| IIS | Enable via Windows Features: Internet Information Services → Web Management Tools + World Wide Web Services |
| IIS ASP.NET Core Module | Installed automatically by the .NET Hosting Bundle |
| SQL Server | SQL Server 2019+ (LocalDB acceptable for DEV); SQL Server Express or full for UAT/PROD |
| SMTP | Local SMTP relay (e.g. [smtp4dev](https://github.com/rnwood/smtp4dev)) for DEV; real SMTP for UAT/PROD |

## 2. One-Time IIS Setup

### 2.1 Create Application Pool

For each environment, create a dedicated Application Pool:

| Pool Name | .NET CLR Version | Managed Pipeline |
|-----------|-----------------|-----------------|
| `MPSIP_DEV` | No Managed Code | Integrated |
| `MPSIP_UAT` | No Managed Code | Integrated |
| `MPSIP_PROD` | No Managed Code | Integrated |

> "No Managed Code" is required for .NET Core / .NET 5+ apps hosted in IIS.

### 2.2 Create IIS Site & Applications

```
IIS Site: MPSIP
  Binding: https, port 443 (or http 80 for DEV)
  Physical path: C:\inetpub\wwwroot\mpsip\prod\   ← PROD root app

Sub-applications:
  /dev   → C:\inetpub\wwwroot\mpsip\dev\   (App Pool: MPSIP_DEV)
  /uat   → C:\inetpub\wwwroot\mpsip\uat\   (App Pool: MPSIP_UAT)
```

PROD maps to the site root; DEV and UAT are sub-applications.

### 2.3 Set Application Pool Identity Permissions

Grant the App Pool identity (`IIS AppPool\MPSIP_DEV` etc.) **Read** permission on the publish folder and **Read/Write** on the `logs/` subfolder.

## 3. Database Setup

### 3.1 Create Databases
```sql
CREATE DATABASE MPSIP_DEV;
CREATE DATABASE MPSIP_UAT;
CREATE DATABASE MPSIP_PROD;
```

### 3.2 Create Login & User
```sql
-- Repeat for each DB, replacing DB name
USE MPSIP_DEV;
CREATE LOGIN mpsip_dev WITH PASSWORD = '<strong-password>';
CREATE USER mpsip_dev FOR LOGIN mpsip_dev;
ALTER ROLE db_datareader ADD MEMBER mpsip_dev;
ALTER ROLE db_datawriter ADD MEMBER mpsip_dev;
GRANT EXECUTE TO mpsip_dev;   -- required for stored procedures
```

### 3.3 Run Migrations
Migrations run automatically at app startup via `DatabaseMigrator`. Alternatively, run scripts manually in order:
```
V001__CreateSchemaVersion.sql → V002 → ... → V010
```
Then run seed scripts:
```
Seed_OpportunityKinds.sql
Seed_ManufacturingTemplate.sql
Seed_DevData.sql    ← DEV only
```

## 4. Environment Variables

All sensitive configuration is set as **Windows System Environment Variables** (not in `appsettings.*.json`).

| Variable Name | Used By | Example Value |
|--------------|---------|--------------|
| `MPSIP_DEV__ConnectionStrings__DefaultConnection` | DEV | `Server=.\SQLEXPRESS;Database=MPSIP_DEV;User Id=mpsip_dev;Password=...;` |
| `MPSIP_UAT__ConnectionStrings__DefaultConnection` | UAT | `Server=.\SQLEXPRESS;Database=MPSIP_UAT;...` |
| `MPSIP_PROD__ConnectionStrings__DefaultConnection` | PROD | `Server=.\SQLEXPRESS;Database=MPSIP_PROD;...` |
| `MPSIP_DEV__Email__Host` | DEV | `localhost` |
| `MPSIP_UAT__Email__Host` | UAT | `smtp.yourprovider.com` |
| `MPSIP_PROD__Email__Host` | PROD | `smtp.yourprovider.com` |
| `MPSIP_UAT__Email__Username` | UAT | SMTP username |
| `MPSIP_PROD__Email__Username` | PROD | SMTP username |
| `MPSIP_UAT__Email__Password` | UAT | SMTP password |
| `MPSIP_PROD__Email__Password` | PROD | SMTP password |

> Variable naming pattern: `{APP}__{ENV}__Section__Key` allows per-environment overrides.
> Set via: `System Properties → Environment Variables → System Variables → New`.
> Restart the Application Pool after setting variables.

## 5. Publish & Deploy Runbook

### 5.1 Build & Publish

```powershell
# From repo root
cd src

# Publish for a specific environment
dotnet publish MPSIP.Web\MPSIP.Web.csproj `
  -c Release `
  -r win-x64 `
  --self-contained false `
  -o "C:\Releases\mpsip\dev" `
  /p:EnvironmentName=Development

# For UAT
dotnet publish MPSIP.Web\MPSIP.Web.csproj `
  -c Release -r win-x64 --self-contained false `
  -o "C:\Releases\mpsip\uat" `
  /p:EnvironmentName=UAT

# For PROD
dotnet publish MPSIP.Web\MPSIP.Web.csproj `
  -c Release -r win-x64 --self-contained false `
  -o "C:\Releases\mpsip\prod" `
  /p:EnvironmentName=Production
```

### 5.2 Deploy to IIS

```powershell
# Stop the App Pool (avoids file-lock errors)
& "C:\Windows\System32\inetsrv\appcmd.exe" stop apppool /apppool.name:"MPSIP_DEV"

# Robocopy publish output to IIS path (preserves directory structure, removes old files)
robocopy "C:\Releases\mpsip\dev" "C:\inetpub\wwwroot\mpsip\dev" /MIR /NJH /NJS

# Start the App Pool
& "C:\Windows\System32\inetsrv\appcmd.exe" start apppool /apppool.name:"MPSIP_DEV"
```

Repeat with `MPSIP_UAT` / `MPSIP_PROD` and their respective paths for UAT and PROD.

### 5.3 web.config (auto-generated by publish)

The `dotnet publish` command generates `web.config` automatically for IIS hosting. Verify it contains:
```xml
<aspNetCore processPath="dotnet"
            arguments=".\MPSIP.Web.dll"
            stdoutLogEnabled="false"
            stdoutLogFile=".\logs\stdout"
            hostingModel="inprocess" />
```

Create the `logs\` subfolder in the publish output if it doesn't exist:
```powershell
New-Item -ItemType Directory -Force -Path "C:\inetpub\wwwroot\mpsip\dev\logs"
```

## 6. `ASPNETCORE_ENVIRONMENT` Setup

Set the environment name in IIS Application Pool environment variables (not System-wide):

1. Open IIS Manager → Application Pools → `MPSIP_DEV` → Advanced Settings → Environment Variables
2. Add: `ASPNETCORE_ENVIRONMENT = Development`
3. Repeat: `MPSIP_UAT` → `UAT`, `MPSIP_PROD` → `Production`

## 7. Smoke Test Checklist

Run after each deployment:

### DEV
- [ ] `https://localhost/dev` loads the login page without errors
- [ ] Login with `owner@mpsip.dev` / `Dev@12345` succeeds → dashboard loads
- [ ] Dashboard shows the "Demo Steel Frame Project" card
- [ ] Navigate to Projects → project detail loads with phases and tasks
- [ ] Log a contribution → appears in contributions list
- [ ] Notification bell shows unread count

### UAT
- [ ] `https://<server>/uat` loads the login page
- [ ] Register as owner → login → dashboard shows empty state
- [ ] Invite a partner → invitation email received (check SMTP)
- [ ] Accept invitation → partner registered → dashboard shows project
- [ ] All 9 navigation sections load without errors

### PROD
- [ ] `https://<server>` loads the login page with correct app title
- [ ] SSL certificate valid; no browser security warnings
- [ ] Owner registers successfully
- [ ] All pages render correctly with no console errors
- [ ] Database connectivity confirmed (no 500 errors)

## 8. Rollback Procedure

If a deployment fails:

```powershell
# Stop app pool
& "C:\Windows\System32\inetsrv\appcmd.exe" stop apppool /apppool.name:"MPSIP_PROD"

# Restore previous release (keep a dated backup before each deploy)
robocopy "C:\Releases\mpsip\prod_backup_YYYYMMDD" "C:\inetpub\wwwroot\mpsip\prod" /MIR /NJH /NJS

# Start app pool
& "C:\Windows\System32\inetsrv\appcmd.exe" start apppool /apppool.name:"MPSIP_PROD"
```

> **Best practice**: Before each production deploy, copy the current IIS folder to `C:\Releases\mpsip\prod_backup_{date}`.
