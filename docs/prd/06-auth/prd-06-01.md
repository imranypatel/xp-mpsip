# Authentication Module PRD (prd-06-01)

> **Concern**: 06-auth | **Version**: v0.8.0 | **Phase**: P3

---

## Goal
Implement custom authentication for MPSIP using Dapper + stored procedures. Covers user login, self-registration via invitation token, session management, and the three auth Blazor pages.

---

## 1. Auth Flow Overview

```
Owner registers → Login → Session cookie issued
                              ↓
Owner invites partner (email + project) → InvitationToken created → Email sent
                              ↓
Partner clicks link → /accept-invitation?token={guid}
                              ↓
Partner registers (name + password) → Token redeemed → Partner record activated → Login
```

public class InvitationToken
{
    public int Id { get; set; }
    public Guid Token { get; set; }
    public int ProjectId { get; set; }
    public string Email { get; set; } = "";
    public DateTime ExpiresAt { get; set; }
    public DateTime? UsedAt { get; set; }
    public bool IsExpired => DateTime.UtcNow > ExpiresAt;
    public bool IsUsed => UsedAt.HasValue;
    public bool IsValid => !IsExpired && !IsUsed;
}

## 4. Infrastructure Layer (MPSIP.Infrastructure)

### `AuthRepository.cs`
Uses `sp_Auth_GetUserByEmail`, `sp_Auth_CreateUser`, `sp_Auth_CreateInvitation`, `sp_Auth_RedeemInvitation`, `sp_Auth_GetUserById`.

```csharp
public async Task<(AuthUserDto?, string?, string?)> GetUserForLoginAsync(string email)
{
    using var conn = _factory.Create();
    var row = await conn.QuerySingleOrDefaultAsync(
        "sp_Auth_GetUserByEmail",
        new { Email = email },
        commandType: CommandType.StoredProcedure);
    if (row == null) return (null, null, null);
    return (new AuthUserDto(row.Id, row.Email, row.DisplayName, row.IsActive),
            row.PasswordHash, row.Salt);
}
```

## 5. Custom AuthenticationStateProvider

```csharp
// MPSIP.Web/Services/MpsipAuthStateProvider.cs
public class MpsipAuthStateProvider : AuthenticationStateProvider
{
    private readonly IHttpContextAccessor _ctx;
    private readonly AuthService _authService;

    public override async Task<AuthenticationState> GetAuthenticationStateAsync()
    {
        var userIdClaim = _ctx.HttpContext?.User.FindFirst(ClaimTypes.NameIdentifier);
        if (userIdClaim == null)
            return new AuthenticationState(new ClaimsPrincipal(new ClaimsIdentity()));

        var user = await _authService.GetUserByIdAsync(int.Parse(userIdClaim.Value));
        if (user == null || !user.IsActive)
            return new AuthenticationState(new ClaimsPrincipal(new ClaimsIdentity()));

        var identity = new ClaimsIdentity(new[]
        {
            new Claim(ClaimTypes.NameIdentifier, user.Id.ToString()),
            new Claim(ClaimTypes.Email, user.Email),
            new Claim(ClaimTypes.Name, user.DisplayName)
        }, "cookie");
        return new AuthenticationState(new ClaimsPrincipal(identity));
    }

    public void NotifyAuthStateChanged() =>
        NotifyAuthenticationStateChanged(GetAuthenticationStateAsync());
}
```

    - MudTextField: Confirm Password
    - MudButton: "Join Project" → AcceptInvitationAsync → auto-login → /dashboard

## 7. Cookie Auth Helpers

```csharp
// Extension method used in Login and AcceptInvitation pages
public static async Task SignInAsync(
    this HttpContext ctx, AuthUserDto user, bool isPersistent = false)
{
    var claims = new List<Claim>
    {
        new(ClaimTypes.NameIdentifier, user.Id.ToString()),
        new(ClaimTypes.Email, user.Email),
        new(ClaimTypes.Name, user.DisplayName)
    };
    var identity = new ClaimsIdentity(claims, CookieAuthenticationDefaults.AuthenticationScheme);
    await ctx.SignInAsync(CookieAuthenticationDefaults.AuthenticationScheme,
        new ClaimsPrincipal(identity),
        new AuthenticationProperties { IsPersistent = isPersistent });
}
```

## Acceptance Criteria
- [ ] Owner can register at `/register`; account created in DB with BCrypt hash
- [ ] Owner can log in at `/login`; session cookie issued; redirected to `/dashboard`
- [ ] Unauthenticated requests to protected pages redirect to `/login`
- [ ] Partner invitation email contains valid `/accept-invitation?token={guid}` link
- [ ] Partner clicks link, completes registration, auto-logged in, redirected to dashboard
- [ ] Expired (>48h) or already-used tokens show a friendly error on `/accept-invitation`
- [ ] Logout clears cookie and redirects to `/login`
