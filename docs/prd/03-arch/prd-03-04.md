## Spec

### What already works (no changes needed)
- `src/MPSIP.Web/Properties/launchSettings.json` has `http` (port 5093) and `https` (port 7098) profiles
- `appsettings.Development.json` points at LocalDB
- `Program.cs` auto-runs DB migrations + seeds at startup
- Therefore `dotnet run` from the right directory is all that's needed

### Deliverables

| Deliverable | Path | Purpose |
|-------------|------|---------|
| Runner script | `scripts/run-dev.ps1` | One-command launch: prereq check → LocalDB start → build → run → open browser |
| How-to doc | `docs/how-to/kestrel-run.md` | Step-by-step guide for any team member |

### `scripts/run-dev.ps1` behaviour

1. Verify `dotnet` CLI is on PATH — abort with helpful message if not
2. Start `sqllocaldb MSSQLLocalDB` (idempotent — safe to call when already running)
3. `dotnet build` the solution — abort on failure
4. `dotnet run --project src/MPSIP.Web --launch-profile http` (or `https` with `-Https` flag)
5. Open browser to the app URL in the background before `dotnet run` blocks

### `docs/how-to/kestrel-run.md` sections

- Prerequisites
- Quick start (one command)
- Manual commands (for IDE users)
- http vs https
- First-run notes (migrations, seed data)
- Troubleshooting (LocalDB, port conflicts, cert)
