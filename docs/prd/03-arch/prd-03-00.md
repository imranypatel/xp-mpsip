## Concern Overview

The **Architecture** concern (`03-arch`) defines the technical foundation for the MPSIP application: technology stack, solution structure, design principles, data access patterns, authentication, database management, environment topology, and cross-cutting decisions. All implementation work must conform to the decisions documented here.

## Architecture at a Glance

### Technology Stack

| Concern | Choice |
|---------|--------|
| Framework | .NET 10 Blazor Server |
| UI Components | MudBlazor |
| Database | MS SQL Server |
| Data Access | Dapper (stored procedures only) |
| Authentication | Custom (Dapper + stored procedures; BCrypt; no ASP.NET Identity) |
| Hosting | MS Windows IIS |

### Solution Layout

```
MPSIP.sln
└── src/
    ├── MPSIP.Web/           # Blazor Server — Pages, Components, Layouts
    ├── MPSIP.Application/   # Use cases, services, interfaces, DTOs
    ├── MPSIP.Domain/        # Entities, value objects, domain rules
    └── MPSIP.Infrastructure/ # Dapper repos, DB, email sender
```

**Dependency direction**: `Web → Application → Domain ← Infrastructure`

### Data Access Rules

- **Stored procedures only** — no inline SQL in C# at any layer
- **SP naming**: `sp_[Module]_[Action]` (e.g. `sp_Project_GetById`)
- **DB objects**: tables PascalCase; views `vw_`; functions `fn_`; indexes `ix_`
- **Migrations**: `V{###}__Description.sql` under `Infrastructure/Database/Migrations/`

### Environments

| Env | IIS Path | SQL DB |
|-----|----------|--------|
| DEV | `/dev` | `MPSIP_DEV` |
| UAT | `/uat` | `MPSIP_UAT` |
| PROD | `/` | `MPSIP_PROD` |

### Key Cross-Cutting Decisions

- `OwnerId` on all domain tables (multi-tenancy readiness)
- `CreatedAt/By`, `ModifiedAt/By` audit columns on all major tables
- `IsDeleted` soft-delete flag — no hard deletes in production
- Credentials in Windows environment variables — never in source control
