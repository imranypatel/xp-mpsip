# DatabaseMigrator SQL File Discovery Fix (prd-03-06)

> **Concern**: 03-arch | **Version**: v0.15.0 | **Phase**: bug fix

---

## Initial Verbatim

> Followed manual override instructions in docs/how-to/kestrel-run-sqlserver.md.
> In PS, ran:
>     $env:ASPNETCORE_ENVIRONMENT = "Development"
>     $env:ConnectionStrings__DefaultConnection = "{valid connection string}"
>     dotnet run --project src/MPSIP.Web --launch-profile http
> App launches, successfully connects to db, Creates SchemaVersion table
> But neither applying stored procedures nor seed data through Migrations.

---

## Root Cause Analysis

`DatabaseMigrator.GetDatabaseDir()` uses:

```csharp
var asmDir = Path.GetDirectoryName(Assembly.GetExecutingAssembly().Location)!;
```

When running `dotnet run --project src/MPSIP.Web`, all referenced DLLs including `MPSIP.Infrastructure.dll` are copied to the **Web project's** output:

```
src/MPSIP.Web/bin/Debug/net10.0/MPSIP.Infrastructure.dll   ← asmDir resolves here
```

**First check:** `{asmDir}/Database/StoredProcedures` — does not exist (SQL files were never copied there).

**Fallback:** walks ancestors looking for a directory named `MPSIP.Infrastructure`:
```
net10.0 → Debug → bin → MPSIP.Web → src → {repo root} → null
```
None match `MPSIP.Infrastructure` — fallback fails silently, returns non-existent path.

`GetStoredProcedureScripts()` and `GetSeedScripts()` both return `[]`.  
`EnsureSchemaVersionTable()` runs inline T-SQL (no file needed) — that's why the SchemaVersion table IS created.

---

## Fix

Copy SQL files to the build output so the **first path check** succeeds without any logic changes to `DatabaseMigrator.cs`.

### `MPSIP.Infrastructure.csproj`
Add `<Content>` items — copies SQL files to Infrastructure's own output (supports future unit/integration tests that run Infrastructure directly).

### `MPSIP.Web.csproj`
Add linked `<Content>` items pointing at `../MPSIP.Infrastructure/Database/**/*.sql` — copies them into `MPSIP.Web/bin/Debug/net10.0/Database/...` preserving relative structure.

This makes `Path.Combine(asmDir, "Database", sub)` resolve to an existing directory, so `GetDatabaseDir` returns on the first check for all three subdirectories (Migrations, StoredProcedures, Seeds).

Works identically for `dotnet run`, `dotnet publish`, and `scripts/run-dev*.ps1`.
