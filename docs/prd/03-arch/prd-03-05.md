## Spec

### How .NET config override works
Environment variables named `ConnectionStrings__DefaultConnection` override any `appsettings*.json` value at runtime (ASP.NET Core config precedence: env vars > appsettings). The script sets this variable before calling `dotnet run`, so no code changes are needed.

### `scripts/run-dev-sqlserver.ps1` behaviour

| Step | Action |
|------|--------|
| 1 | Verify .NET SDK on PATH |
| 2 | Verify `sqlcmd` or `Invoke-Sqlcmd` available |
| 3 | Create database if not exists (idempotent `IF NOT EXISTS`) |
| 4 | Create SQL login + user + permissions if `-SqlAuth` (idempotent) |
| 5 | Build solution |
| 6 | Set `ConnectionStrings__DefaultConnection` env var |
| 7 | Run Kestrel + open browser |

### Script parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `-Instance` | `.\SQLEXPRESS` | SQL Server instance name |
| `-Database` | `MPSIP_DEV` | Database name to create/use |
| `-WinAuth` | `$true` | Windows Integrated Authentication |
| `-SqlAuth` | `$false` | Use SQL Server Authentication |
| `-SqlUser` | `mpsip_dev` | SQL login name (SQL Auth only) |
| `-SqlPassword` | _(required if -SqlAuth)_ | SQL login password |
| `-Https` | `$false` | Use HTTPS Kestrel profile |
| `-NoBrowser` | `$false` | Skip browser open |
| `-NoBuild` | `$false` | Skip build step |
